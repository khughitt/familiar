Every Claude Code Stop maps to done (src/adapters/claude-code.js HOOK_EVENTS), so ending a turn to wait on a background subagent or workflow plays the niri-desktop done popup (integrations/niri-desktop, state changes into done/error) and the niri done impulse (integrations/niri/signal.js), as if the work had finished. The subagent's own PreToolUse then sets working, so one delegation plays the popup twice: at launch and at the real end. The user sees this as an alert at subagent launch.

Evidence (hq-d121c3, 2026-10-19, Claude Code 2.1.302; times UTC): the Stop payload's background_tasks is documented in the bundle as in-flight background work (running/pending + backgrounded) so hooks can distinguish a finished session from one paused waiting for background work to wake it; each entry has a type label (subagent, workflow, teammate, cloud session, shell, monitor, ...). From 2026-10-18 02:03 to 2026-10-19 09:20, 72 main-session turn ends had pendingBackgroundAgentCount or pendingWorkflowCount >= 1 and each ran familiar hook Stop; example: an hq session at 2026-10-19 09:19:19 (pendingBackgroundAgentCount 1). When the work completes Claude re-invokes the session and its final Stop arrives with nothing in flight. Details: hq docs/notes/2026-10-15-agent-attention-brief.md, section 'Claude and workspace attention, 2026-10-19'.

Approach: gate on task type, not on any running task. Treat agent-type entries (subagent, workflow, teammate, cloud session: the types Claude's own idle check suppresses for: local_agent, local_workflow, in_process_teammate, remote_agent) with status running or pending as in flight, and reduce such a Stop to working instead of done. Shells and monitors must not: a dev server or Monitor left running would otherwise hold every later Stop at working, with no done signal and the idle prompt already reduced to idle. Keep done for shell-only and monitor-only Stops. Record the reported counts by type: on idle_prompt only shells and monitors should reduce needs-input to idle, because Claude never sends idle_prompt while an agent-type task runs, so a carried agent count there is stale (Familiar does not hear SubagentStop). Decide whether a Stop with only session_crons pending (a scheduled wakeup or /loop) counts as in flight. Keep BEL behaviour unchanged.

Verification: adapter/transaction tests for Stop with a running subagent, a pending workflow, a persistent shell only, a monitor only, an empty list, and session_crons only; an idle_prompt after an agent-only Stop still becomes needs-input; the shell idle_prompt reduction still holds. Codex is out of scope unless its main turn is shown to end while it waits on its subagents (unchecked).
